# 주간 정리 작성 기준

우리는 AI 생성 서비스 회사입니다. 새 이미지·영상·오디오 생성 모델을 경쟁사보다 빨리 서비스에 붙이는 것이 목표입니다.
지난주(`WEEK`, KST 월~일)의 생성 모델 소식을 정리해 Confluence 페이지 본문(`out/weekly_page.md`)과 슬랙 요약(`out/weekly_digest.json`)을 만듭니다.

## 1. 후보 모으기
- `out/weekly_candidates.json`: 데일리 봇이 지난주에 보낸 소식입니다. 여기 있는 것은 모두 후보입니다.
- 웹 검색: 지난주에 발표·출시된 이미지·영상·오디오 생성 모델 소식을 찾습니다. 데일리 봇이 보지 않는 곳(xAI, Alibaba Cloud, ByteDance/BytePlus, Kling, Pika, Microsoft, NVIDIA, GitHub 공개 등)을 특히 확인합니다.
- 날짜가 지난주 범위 밖이면 넣지 않습니다. 단, 지난주에 처음 API·플랫폼에 올라왔다면 넣을 수 있습니다.
- LLM, 음성 인식, 3D 전용, 개인 파인튜닝·LoRA, 비공식 경량화는 넣지 않습니다.

## 2. 새 모델 5개 고르기 (위일수록 중요)
1. 우리 공급처(Replicate·Runware)에 이미 올라와 바로 붙일 수 있는 모델
2. 주요 회사(Google, OpenAI, ByteDance, Kuaishou(Kling), Alibaba(Qwen·Wan), Black Forest Labs, Runway, Luma, MiniMax, xAI, ElevenLabs, Meta 등)의 대표 모델 새 버전
3. 완전히 새로운 기능(새 입력·출력 방식, 오디오 동시 생성, 긴 길이 등)을 가진 모델

중요한 게 5개가 안 되면 그보다 적게 고릅니다. 숫자를 채우려고 덜 중요한 것을 넣지 않습니다.

## 3. 사실 확인
- 모든 사실(날짜, 모델 ID, 기능, 길이, 해상도, 가격)은 공식 발표·문서·플랫폼 페이지에서 확인한 것만 씁니다. 확인 못 한 항목은 그 줄을 아예 쓰지 않습니다. 추측하지 않습니다.
- 플랫폼 제공 여부는 `out/weekly_catalog.tsv` 에서 모델 이름으로 찾습니다(예: `grep -i seedance out/weekly_catalog.tsv`). 같은 모델·같은 버전이 있으면 그 행의 url 을 그대로 씁니다. 비슷한 이전 버전만 있으면 없는 것으로 봅니다. 목록 읽기에 실패한 플랫폼(`CATALOG_OK` 의 fail)은 해당 줄을 쓰지 않습니다.

## 4. 페이지 본문 형식 (`out/weekly_page.md`, 마크다운)
아래 순서와 모양을 따릅니다. 문체는 "~했습니다"체, 한국어. 긴 줄표(—)는 쓰지 말고 "-" 를 씁니다.

```
## <모델 이름>

<만든 곳>이 <날짜> **<모델 이름>**을 <어디에> 공개했습니다. <이전 대비 달라진 점이나 핵심 한 문장>. [출처](url)

- **모델 ID:** `<id>`
- **기능:** 텍스트→영상, 이미지→영상, ...
- **영상 길이:** ...
- **해상도:** ...
- **입력:** ...
- **오디오:** ...
- **가격:** ...
- **API:** <제공처>. [API 문서](url)
- **Replicate:** 제공. [모델 페이지](url)
- **Runware:** 제공. [모델 페이지](url)
- **fal:** 제공. [모델 페이지](url)
- **<제공 안 되는 플랫폼들>:** 제공 확인되지 않음.
```
- 해당 없는 줄(예: 이미지 모델의 영상 길이)은 뺍니다. 오픈 가중치면 **라이선스**, **Hugging Face**, **GitHub** 줄을 넣습니다.
- 새 모델 5개 다음에 아래 두 절을 붙입니다. 내용이 없으면 그 절을 뺍니다.

```
## 기존 서빙 모델 업데이트

## <모델 이름>

<무엇이 바뀌었는지 한두 문장>

- **Replicate:** ...
- **가격:** ...

## 출시 예정 레이더

- **<모델 이름>:** <언제·어디서 공개 예정인지, 공개 안 된 정보> 
```
- `out/served_models.json` 에 이미 있는 모델(같은 모델·같은 버전)은 새 모델 5개에 넣지 않고 이 절에 넣습니다.
- "기존 서빙 모델 업데이트"는 `out/served_models.json` 의 displayName 과 같은 모델(같은 계열의 새 기능·새 플랫폼 제공·가격 변경)만 넣습니다. 제공 종료 소식은 넣지 않습니다.
- "출시 예정 레이더"는 지난주에 발표됐지만 아직 쓸 수 없는 모델입니다.

## 5. 슬랙 요약 (`out/weekly_digest.json`)
새 모델(고른 만큼)을 페이지와 같은 순서로 씁니다. 슬랙만 읽어도 무슨 모델인지 알 수 있어야 합니다.
- modality: "이미지", "영상", "오디오", "멀티모달" 중 하나. 메시지에서 모델 이름 앞에 [영상] 처럼 붙습니다
- summary: 무엇이고 우리에게 왜 중요한지 한 문장(50자 안팎)
- features: 기본 특징 2~4개. 한 항목에 한 가지 사실만 짧게(30자 안팎). 할 수 있는 작업, 해상도·길이, 참조 입력 수, 오디오, 속도·가격 같은 핵심 수치 위주. 페이지에 쓴 확인된 사실만
- available: 지금 쓸 수 있는 곳 한 줄(예: "Runware · fal.ai · MiniMax API"). 아직 쓸 수 없으면 "출시 예정"
```json
{"page_url": "<만든 Confluence 페이지 주소>",
 "items": [
  {"model_name": "MiniMax H3-Image", "maker": "MiniMax", "modality": "이미지",
   "summary": "Runware·fal에 바로 올라온 4K 오픈 가중치 이미지 모델",
   "features": ["4K(4096×4096) 이미지를 10초 안에 생성", "참조 이미지 최대 16장", "생성과 편집을 한 모델로"],
   "available": "Runware · fal.ai · MiniMax API · Hugging Face"}
 ]}
```
